## 2. うまくいったこと（Keep）

### 2.1 技術選定

- **Next.js 16 App Router の採用:** Server ActionsとAPI Routesの使い分けにより、フォーム処理はServer Actions、ポーリングデータはAPI Routesと、適材適所のアーキテクチャが実現できた
- **Prisma 7 の型安全性:** TypeScriptとの統合により、データベース操作時の型エラーを開発時に検出でき、ランタイムエラーが大幅に減少した
- **Zod v4 による統一バリデーション:** サーバーサイドとクライアントサイドで同じバリデーションスキーマを共有し、入力検証の実装が効率的かつ一貫性のあるものになった
- **Tailwind CSS v4:** ユーティリティファーストのアプローチにより、CSSの命名に悩むことなく迅速なUI開発ができた

### 2.2 アーキテクチャ設計

- **ディレクトリ構造の明確さ:** actions/ validations/ lib/ components/ の分離により、コードの見通しが良く、新規機能追加時の迷いが少なかった
- **Server Actions + FormData パターン:** useActionStateとFormDataの組み合わせにより、フォーム処理のボイラーplate が最小限に抑えられた
- **SWR ポーリング:** ダッシュボードの30秒ポーリングにより、WebSocket無しで疑似リアルタイム更新を実現。実装コストとユーザー体験のバランスが良かった
- **論理削除の採用:** isActiveフラグによる論理削除で、参照整合性を維持しつつ安全にデータを非活性化できた

### 2.3 開発プロセス

- **スプリント計画の精度:** 6スプリント全てで計画SPを達成。ストーリーポイントの見積もりが適切だった
- **Phase分割:** Phase 1（HACCP管理）とPhase 2（原価管理）の明確な分離により、優先度に基づいた段階的な開発ができた
- **ロット自動採番ロジック:** PLT-YYYYMMDD-NNN / MLT-YYYYMMDD-NNN の採番ルールが直感的で、製造現場での運用に適している
- **温度異常自動検出:** 温度記録時に設備の閾値と自動比較してアラートを生成する仕組みが、HACCP管理の核心要件を的確に実現した

### 2.4 品質管理

- **Zodバリデーションの日本語メッセージ:** 「設備を選択してください」「数量は0より大きい値を入力してください」等、ユーザーフレンドリーなエラーメッセージ
- **ロールベースアクセス制御:** requireSession() / requireRole() のシンプルな実装で、確実な権限チェックを実現
- **自己削除防止:** ユーザー管理での自己削除防止チェックにより、管理者が自分自身を誤って削除するリスクを排除

## 3. 改善すべきこと（Problem）

### 3.1 機能面の課題

- **製造実績の編集・削除未実装:** 誤入力時の修正手段がDB直接操作に限られている。v1.1.0で優先的に実装すべき
- **ページネーション未対応:** 一覧画面のtake制限（50件/100件）のみで、件数が多い場合のUXが不十分
- **パスワードリセット機能なし:** ユーザーが自身でパスワードを変更する手段がない
- **帳票出力機能なし:** HACCP記録帳のPDF出力が未実装。保健所への提出用書類の作成に課題

### 3.2 技術的課題

- **製品ロット自動採番の競合リスク:** 同時アクセス時にfindFirst + 連番計算の間に競合が発生する可能性がある。トランザクションまたはシーケンスの使用を検討すべき
- **Prisma v7 の adapter 必須仕様:** `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })` の初期化パターンが直感的でなく、初期セットアップで混乱が生じた
- **ダッシュボードAPI のN+1問題:** production-chart APIで7回のクエリ（7日分）、temperature-status APIでN回のクエリ（設備数分）が発行されている。パフォーマンス最適化の余地がある
- **エラーハンドリングの統一性:** Server Actionsの一部で`{ error: string }`返却、一部で例外throwと、エラーハンドリングパターンが統一されていない

### 3.3 テスト面の課題

- **自動テスト未実装:** ユニットテスト、統合テスト、E2Eテストが全て未実装。テスト計画は作成したが、テストコードの実装が追いつかなかった
- **手動テストの属人化:** テスト実行がチームメンバー個人の確認に依存しており、テスト結果の記録・追跡が不十分

### 3.4 ドキュメント面の課題

- **インラインコメントの不足:** 複雑なビジネスロジック（ロス率計算、達成率分析）のコメントが不十分
- **開発環境セットアップの手順:** 初期セットアップで環境固有の問題（PostgreSQLのPATH設定等）に時間を取られた

## 7. まとめ

v1.0.0は計画通りのスケジュール（6スプリント）で全42ストーリー（191 SP）を完了し、22画面・31ルートの川上食品HACCP管理システムをリリースできた。技術選定（Next.js 16 + Prisma 7 + Zod v4）は適切であり、開発生産性と品質の両立を実現した。

最大の課題は自動テストの未実装であり、v1.1.0以降で優先的に対応する。また、製造実績の編集・削除機能やPDF帳票出力など、ユーザーからの改善要望にも継続的に対応していく。

チーム全体として、HACCP管理という食品安全に直結するシステムの開発に高いモチベーションを持って取り組めたことは、プロジェクト成功の大きな要因である。
