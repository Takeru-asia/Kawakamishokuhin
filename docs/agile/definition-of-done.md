---

## 1. 概要

完了の定義（DoD）は、プロダクトバックログアイテムが「完了」と判断されるために満たすべき基準の一覧である。すべてのアイテムは、これらの基準を満たさない限り「完了」とは見なされない。

---

## 2. コーディング基準

### 2.1 コード品質

- [ ] TypeScriptの型チェックがエラーなしで通過する（`npx tsc --noEmit`）
- [ ] ESLintのチェックがエラーなしで通過する（`npm run lint`）
- [ ] `"use server"` ディレクティブが適切に付与されている（Server Actions）
- [ ] `"use client"` ディレクティブが適切に付与されている（Client Components）
- [ ] 不要なconsole.logやデバッグコードが削除されている
- [ ] コメントが必要な箇所に日本語コメントが記載されている

### 2.2 コーディング規約

- [ ] ファイル名はケバブケース（例: `production-record.tsx`）またはキャメルケース（例: `productionRecord.ts`）
- [ ] コンポーネント名はパスカルケース（例: `ProductionRecordForm`）
- [ ] 関数名はキャメルケース（例: `createProductionRecord`）
- [ ] DBカラム名はスネークケース（Prismaの `@@map` 使用）
- [ ] インデントは2スペース
- [ ] インポートの順序: 外部ライブラリ → 内部モジュール

### 2.3 アーキテクチャ遵守

- [ ] Server Actionsは `src/actions/` に配置されている
- [ ] バリデーションスキーマは `src/validations/` に配置されている
- [ ] ページコンポーネントは `src/app/(dashboard)/` 配下に配置されている
- [ ] 共通コンポーネントは `src/components/` に配置されている
- [ ] ユーティリティ関数は `src/lib/` に配置されている
- [ ] パス解決に `@/` エイリアスを使用している

---

## 3. 機能要件

### 3.1 ユーザーストーリー

- [ ] ユーザーストーリーの全受入条件が満たされている
- [ ] 「As a [role], I want [feature], so that [benefit]」の目的が達成されている
- [ ] エッジケース（空入力、境界値、不正入力）が考慮されている

### 3.2 バリデーション

- [ ] 全入力フォームにZodバリデーションが適用されている
- [ ] バリデーションエラーメッセージが日本語で表示される
- [ ] サーバーサイドでのバリデーションが実装されている（クライアントのみは不可）
- [ ] 必須フィールドの未入力が適切にハンドリングされている

### 3.3 認証・認可

- [ ] 認証が必要な操作にrequireSession()が適用されている
- [ ] 権限が必要な操作にrequireRole()が適用されている
- [ ] 適切なロール（ADMIN/MANAGER/WORKER）で動作確認されている

---

## 4. テスト要件

### 4.1 テスト実施

- [ ] 該当するテストケース（テスト計画参照）が全て実行済み
- [ ] 高優先度テストケースの合格率: 100%
- [ ] 中優先度テストケースの合格率: 95%以上
- [ ] 発見されたバグがチケット化されている

### 4.2 手動テスト

- [ ] 該当する全画面でのUI操作テストが完了している
- [ ] 正常系フローが動作確認されている
- [ ] 異常系（エラーハンドリング）が動作確認されている
- [ ] ロール別（ADMIN/MANAGER/WORKER）での動作確認が完了している

### 4.3 クロスブラウザテスト

- [ ] Chrome（最新版）で動作確認済み
- [ ] Firefox（最新版）で動作確認済み（推奨）
- [ ] Safari（最新版）で動作確認済み（推奨）

---

## 5. パフォーマンス基準

- [ ] ページの初回ロード時間が3秒以内
- [ ] Server Actionのレスポンスが2秒以内
- [ ] API Routeのレスポンスが1秒以内
- [ ] SWRポーリングがUIをブロックしない

---

## 6. セキュリティ基準

- [ ] パスワードがbcryptでハッシュ化されている（平文保存しない）
- [ ] JWTトークンがhttpOnly Cookieに格納されている
- [ ] SQLインジェクション対策（Prismaのパラメータバインド）が適用されている
- [ ] XSS対策（Reactの自動エスケープ）が確認されている
- [ ] 認証トークンに有効期限が設定されている
- [ ] 機密情報（パスワードハッシュ）がAPIレスポンスに含まれていない

---

## 7. UI/UX基準

### 7.1 デザイン

- [ ] Tailwind CSSのユーティリティクラスで統一的にスタイリングされている
- [ ] 共通UIコンポーネント（Button, Input, Table等）を使用している
- [ ] 川上食品のブランドカラー（緑系: #1a5f2a）が適用されている
- [ ] アイコンはlucide-reactから統一的に使用している

### 7.2 ユーザビリティ

- [ ] フォーム送信時のローディング状態が表示される
- [ ] エラーメッセージが日本語でわかりやすく表示される
- [ ] 成功時のフィードバック（画面遷移 or 成功メッセージ）がある
- [ ] ナビゲーション（サイドバー）の現在位置がハイライトされている

### 7.3 アクセシビリティ

- [ ] lang属性が "ja" に設定されている
- [ ] フォーム要素にラベルが設定されている
- [ ] テーブルにヘッダー行が設定されている

- [ ] 必要なインデックスが設定されている

## 11. チェックリストまとめ

### スプリント内のバックログアイテム完了時

1. **コーディング:** TypeScript型チェック通過、ESLint通過、規約遵守
2. **機能:** 受入条件100%達成、バリデーション実装、認証・認可適用
3. **テスト:** 該当テストケース全実行、手動テスト完了
4. **セキュリティ:** パスワードハッシュ化、httpOnly Cookie、パラメータバインド
5. **UI/UX:** 共通コンポーネント使用、エラーメッセージ日本語化、フィードバック表示
6. **DB:** スキーマ準拠、マイグレーション完了
7. **ビルド:** `npm run build` 成功

### リリース時の追加チェック

1. **デプロイ:** 本番ビルド成功、環境変数設定、DB マイグレーション適用
2. **ドキュメント:** API仕様書・DB設計書・リリースノート更新
3. **セキュリティ:** JWT_SECRET変更、SSL設定確認
4. **バックアップ:** データベースバックアップ取得
5. **監視:** ログ出力確認、エラーモニタリング設定
