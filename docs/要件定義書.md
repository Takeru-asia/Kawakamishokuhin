## 1. はじめに

### 1.1 目的

本文書は、川上食品株式会社（以下「甲」）が導入する「HACCP管理システム」の要件を定義するものである。本システムの開発をサムライテクノロジー株式会社（以下「乙」）が請け負うにあたり、甲乙間で機能・仕様について合意形成を図ることを目的とする。

### 1.2 背景

2021年6月より全食品事業者にHACCPに沿った衛生管理が義務化された。甲は豆腐製品の製造販売を主業とし、現在は紙ベース・Excel管理で温度記録や衛生管理を行っているが、以下の課題を抱えている。

- **記録の手間**: 温度記録、製造実績、衛生検査の記録が紙ベースで煩雑
- **トレーサビリティの困難**: 原材料から製品への追跡が紙台帳では時間がかかる
- **異常検知の遅延**: 温度異常の発見が巡回時に限定される
- **データ活用の不足**: 製造目標・ロス率の分析がリアルタイムに行えない

### 1.3 文書の適用範囲

本文書は、HACCP管理システムの全機能に関する要件を定義する。本文書に記載された内容をもって甲の承認を得たのち、乙は設計・開発に着手するものとする。

## 2. システム概要

### 2.1 システム名称

**川上食品 HACCP管理システム**

### 2.2 システムの目的

HACCP（Hazard Analysis and Critical Control Points）に基づく食品安全管理を効率化し、以下を実現する。

1. **温度管理の自動化**: 設備温度の記録と異常自動検知
2. **トレーサビリティの確保**: 原材料ロットから製品ロットまでの完全追跡
3. **衛生管理の記録化**: 清掃・害虫駆除等の衛生検査記録のデジタル化
4. **製造管理の効率化**: 製造実績の登録と目標達成率の可視化
5. **ロス管理の強化**: ロス発生の記録と分析による原価改善

### 2.3 対象業務

| 業務領域 | 概要 |
|----------|------|
| 温度管理 | 冷蔵庫・冷凍庫・加熱設備の温度記録と異常検知 |
| 製造管理 | 製造実績の登録、製品ロットの採番 |
| ロット管理 | 原材料ロット・製品ロットの管理とトレーサビリティ |
| 衛生管理 | 清掃・害虫駆除・水質検査・廃棄物管理の記録 |
| 製造目標管理 | 月次製造目標の設定と達成率分析 |
| ロス管理 | 製品ロスの記録と原因分析 |
| マスタ管理 | 製品・原材料・設備・ユーザーの基本情報管理 |

## 5. 機能要件

### 5.1 機能一覧サマリ

| 領域 | 画面数 | API数 | ロジック数 | フェーズ |
|------|:------:|:-----:|:----------:|:--------:|
| 認証 | 1 | 3 | - | 共通 |
| ダッシュボード | 1 | 5 | - | 共通 |
| 製造管理 | 3 | 3 | 3 | P1 |
| 温度管理 | 3 | 3 | 3 | P1 |

| 衛生管理 | 2 | 2 | - | P1 |
| 製造目標 | 3 | 3 | 2 | P2 |
| ロス管理 | 3 | 3 | 2 | P2 |
| マスタ管理 | 4 | 16 | - | 共通 |
| **合計** | **22** | **42** | **11** | - |

### 5.2 認証機能

#### F-AUTH-01: ログイン

- ユーザーはメールアドレスとパスワードでシステムにログインする
- 認証成功時、ダッシュボードへ遷移する
- 認証失敗時、エラーメッセージを表示する
- セッション有効期限: 8時間

#### F-AUTH-02: ログアウト

- ユーザーはヘッダーのログアウトボタンでセッションを終了する
- ログアウト後、ログイン画面へ遷移する

#### F-AUTH-03: セッション管理

- 未認証ユーザーは全画面においてログイン画面へリダイレクトされる
- APIリクエストは401エラーを返却する

### 5.3 ダッシュボード

#### F-DASH-01: KPIカード表示

4種のKPI（重要業績指標）をカード形式で表示する。

| KPI | 表示内容 | 計算方法 |
|-----|----------|----------|
| 本日の製造数量 | 当日の製造合計数 | 当日のProductionRecordItemの数量合計 |
| 目標達成率 | 当月の達成率（%） | (当月実績合計 / 当月目標合計) × 100 |
| ロス率 | 当月のロス率（%） | (当月ロス合計 / 当月製造合計) × 100 |
| 温度異常件数 | 未対応アラート数 | ステータスがOPENのTemperatureAlertの件数 |

#### F-DASH-02: アラートバナー

- 未対応の温度異常アラートが存在する場合、ダッシュボード上部に警告バナーを表示する
- バナーからアラート管理画面へ遷移できる

#### F-DASH-03: 製造推移グラフ

- 過去7日間の製造数量推移を棒グラフで表示する

#### F-DASH-04: 温度一覧テーブル

- 各設備の最新温度記録を一覧表示する
- 異常温度は赤色で強調表示する

#### F-DASH-05: クイックアクション

- 製造実績登録、温度記録、ロット検索への直接リンクを提供する

#### F-DASH-06: 自動更新

- ダッシュボードのデータは30秒間隔で自動更新する

### 5.4 温度管理

#### F-TEMP-01: 温度記録一覧

- 温度記録を日付・設備でフィルタリングし一覧表示する
- 正常/異常をバッジで色分け表示する（正常: 緑、異常: 赤）
- ページネーション対応（20件/ページ）

#### F-TEMP-02: 温度記録登録

- 設備を選択し、計測温度を入力して記録を登録する
- 記録者は自動的にログインユーザーが設定される
- 備考欄は任意入力

#### F-TEMP-03: 温度異常自動検知

- 温度記録登録時、設備に設定された基準値と比較する
  - 冷蔵・冷凍設備: 計測温度 > 上限値 → 異常
  - 加熱設備: 計測温度 < 下限値 → 異常
- 異常と判定された場合:
  - `is_normal = false` を設定
  - `TemperatureAlert` レコードを自動作成（ステータス: OPEN）

#### F-TEMP-04: アラート管理

- 未対応（OPEN）、確認済み（ACKNOWLEDGED）、解決済み（RESOLVED）のアラートを一覧表示する
- MANAGER以上の権限でステータス変更が可能
- 解決時には是正措置の入力が必須

### 5.5 製造管理

#### F-PROD-01: 製造実績一覧

- 製造実績を日付でフィルタリングし一覧表示する
- ページネーション対応（20件/ページ）

#### F-PROD-02: 製造実績登録

- 製造日を指定し、製品と数量を明細行として複数登録できる
- 登録時に以下を自動処理:
  - 製品ロットの自動採番（PLT-YYYYMMDD-NNN形式）
  - 明細行ごとのProductionRecordItem作成
  - ProductLotの自動作成

#### F-PROD-03: 製造実績詳細

- 製造実績の明細（製品・数量・ロット番号）を表示する

### 5.6 ロット管理

#### F-LOT-01: ロット検索

- 製品ロット・原材料ロットを切り替えて検索できる
- ロット番号、製品名、原材料名でキーワード検索が可能

#### F-LOT-02: 原材料ロット登録

- 原材料ロットを登録する
- ロット番号は自動採番（MLT-YYYYMMDD-NNN形式）
- 入荷日、有効期限、数量、仕入先ロット番号を入力

#### F-LOT-03: トレーサビリティ（前方追跡）

- 原材料ロットから、それを使用して製造された製品ロットを追跡する
- ツリー形式で視覚的に表示する

#### F-LOT-04: トレーサビリティ（後方追跡）

- 製品ロットから、その製造に使用された原材料ロットを追跡する
- ツリー形式で視覚的に表示する

### 5.7 衛生管理

#### F-HYG-01: 衛生記録一覧

- 衛生記録をカテゴリ・日付でフィルタリングし一覧表示する
- 結果をバッジで色分け表示する（合格: 緑、不合格: 赤、対象外: グレー）

#### F-HYG-02: 衛生記録登録

- 衛生カテゴリ（清掃、害虫駆除、水質検査、廃棄物管理）を選択
- 対象設備の選択（任意）
- 検査結果（合格/不合格/対象外）を選択
- 詳細と備考を入力

### 5.8 製造目標管理

#### F-TGT-01: 目標一覧

- 製造目標を年月・製品でフィルタリングし一覧表示する
- 目標数量と達成状況を表示する

#### F-TGT-02: 目標設定

- 製品ごとに月次の製造目標数量を設定する
- MANAGER以上の権限が必要
- 日次目標は月次目標から自動算出

#### F-TGT-03: 達成分析

- 月次の目標対実績をグラフ（棒グラフ）で比較表示する
- 達成率の計算: `(実績合計 / 目標数量) × 100`
- 製品別の達成状況を一覧表示する

### 5.9 ロス管理

#### F-LOSS-01: ロス記録一覧

- ロス記録を日付・製品・カテゴリでフィルタリングし一覧表示する
- ページネーション対応

#### F-LOSS-02: ロス記録登録

- 製品、ロスカテゴリ（製造不良、破損、期限切れ、その他）を選択
- 数量を入力
- ロス率は自動計算: `(ロス数量 / 当月製造数量) × 100`

#### F-LOSS-03: ロスレポート

- 期間を指定してロスの集計データを表示
- カテゴリ別の内訳を円グラフで表示
- 製品別のロス率を一覧表示

### 5.10 マスタ管理

#### F-MST-01: 製品マスタ管理

- 製品の一覧表示・追加・編集・論理削除（無効化）
- 入力項目: 製品コード、製品名、単位
- ADMIN権限が必要

#### F-MST-02: 原材料マスタ管理

- 原材料の一覧表示・追加・編集・論理削除（無効化）
- 入力項目: 原材料コード、原材料名、単位、仕入先
- ADMIN権限が必要

#### F-MST-03: 設備マスタ管理

- 設備の一覧表示・追加・編集・論理削除（無効化）
- 入力項目: 設備コード、設備名、設備種別、設置場所、温度上限値、温度下限値
- 温度基準値は温度異常検知に使用される
- ADMIN権限が必要

#### F-MST-04: ユーザー管理

- ユーザーの一覧表示・追加・編集・無効化
- 入力項目: 氏名、メールアドレス、パスワード、ロール（ADMIN/MANAGER/WORKER）
- ADMIN権限限定

## 9. ビジネスロジック

### 9.1 温度異常自動検知

**トリガー**: 温度記録の登録時

**処理フロー**:

```
温度記録入力
  ↓
設備の温度基準値を取得
  ↓
基準値と比較判定
  ├─ 冷蔵/冷凍設備: 計測温度 > 上限値 → 異常
  └─ 加熱設備: 計測温度 < 下限値 → 異常
  ↓
異常の場合:
  ├─ is_normal = false を設定
  └─ TemperatureAlert を自動作成（status: OPEN）
正常の場合:
  └─ is_normal = true を設定
```

### 9.2 ロット自動採番

**製品ロット**: `PLT-YYYYMMDD-NNN`
- YYYYMMDD: 製造日
- NNN: 当日の連番（001から開始）

**原材料ロット**: `MLT-YYYYMMDD-NNN`
- YYYYMMDD: 入荷日
- NNN: 当日の連番（001から開始）

**例**:
- PLT-20260209-001（2026年2月9日の製品ロット1番目）
- MLT-20260209-003（2026年2月9日の原材料ロット3番目）

### 9.3 トレーサビリティ

**前方追跡（Forward Trace）**:
原材料ロット → LotLink → 製品ロット → 製造実績

「この原材料がどの製品に使われたか」を追跡する。食品事故時の回収範囲特定に使用。

**後方追跡（Backward Trace）**:
製品ロット → LotLink → 原材料ロット → 仕入先情報

「この製品にどの原材料が使われたか」を追跡する。クレーム対応時の原因特定に使用。

### 9.4 製造目標達成率計算

```
達成率（%） = (当月の製造実績合計 / 当月の目標数量) × 100
```

- 製品ごとに月単位で計算
- 目標未設定の場合は「-」と表示

### 9.5 ロス率計算

```
ロス率（%） = (ロス数量 / 当月の製造数量合計) × 100
```

- 製品ごと、およびカテゴリごとに集計可能
- 製造数量が0の場合は「-」と表示

### 9.6 ロール別アクセス制御

各Server Action / APIエンドポイントの実行前に、セッションからユーザーロールを取得し権限チェックを行う。

```
リクエスト受信
  ↓
JWTからセッション情報取得
  ↓
ユーザーロール確認
  ├─ 権限あり → 処理続行
  └─ 権限なし → 403 Forbidden / エラーメッセージ表示
```

| アクセス制御 | ロール別権限チェック（全Server Action/API） |
| 環境変数 | .envファイルのGit管理対象外設定 |
| 通信暗号化 | 本番環境ではHTTPS必須 |

## 14. 用語集

| 用語 | 説明 |
|------|------|
| HACCP | Hazard Analysis and Critical Control Points（危害要因分析重要管理点）。食品の安全を確保するための衛生管理手法 |
| CCP | Critical Control Point（重要管理点）。食品の安全性を確保するために特に重要な工程 |
| トレーサビリティ | 製品の生産から消費までの履歴を追跡できる仕組み |
| ロット | 同一条件で製造された製品または入荷した原材料の管理単位 |
| 前方追跡 | 原材料ロットから製品ロットへの追跡（どの製品に使われたか） |
| 後方追跡 | 製品ロットから原材料ロットへの追跡（何から作られたか） |
| 是正措置 | 異常発生時に問題を解決するために取る対策 |
| KPI | Key Performance Indicator（重要業績評価指標） |
| 論理削除 | データを物理的に削除せず、フラグで無効化する方式 |
| BOM | Bill of Materials（部品構成表）。製品と原材料の配合情報 |
| SWR | Stale-While-Revalidate。キャッシュを表示しつつ裏側でデータを更新する方式 |
| JWT | JSON Web Token。認証情報を安全に伝送するためのトークン形式 |
